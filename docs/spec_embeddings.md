# Spec: pgvector Embedding Pipeline

**Status:** Draft — awaiting approval  
**Date:** 2026-06-26  
**Model:** OpenAI text-embedding-3-small (1536 dimensions)

---

## 1. Product Brief

The scraper repo needs to generate and store a vector embedding for every active product in Postgres. These embeddings will power semantic search in the Next.js price tracker web app via pgvector cosine similarity. The web app handles query-time embedding; this repo handles per-product embedding generation and storage only.

**Scope of this spec:** schema change → embedding module → backfill script → discovery hook.  
**Out of scope:** query-time embedding, similarity search logic, web app changes.

---

## 2. Functional Requirements

| # | Requirement |
|---|---|
| FR-1 | Every active product must have an `embedding vector(1536)` stored in `products.embedding`. |
| FR-2 | Embeddings are generated using OpenAI `text-embedding-3-small` (1536 dimensions). |
| FR-3 | The embedding input is a plain-text string assembled from: `name`, `brand`, `category`, `ai_description` (if not null), price tier label, current price, and specs JSONB as `key: value` pairs. |
| FR-4 | Embeddings are generated at first product discovery (alongside `ai_description`), when `embedding IS NULL`. |
| FR-5 | Embeddings are **never regenerated** unless `embedding IS NULL`. |
| FR-6 | A standalone backfill script generates embeddings for all existing `active = true` products where `embedding IS NULL`. |
| FR-7 | If the OpenAI call fails, the product is skipped and logged — the failure must not block the scrape pipeline or discovery. |
| FR-8 | The backfill script supports `--limit N` (process first N products) and `--dry-run` (print embedding text without calling the API or writing to DB). |

---

## 3. Non-Functional Requirements

| # | Requirement |
|---|---|
| NFR-1 | Rate limiting: 100ms sleep between consecutive OpenAI API calls (both discovery hook and backfill). |
| NFR-2 | The discovery hook must add negligible latency to the discovery pipeline on API success, and zero latency impact on API failure beyond the single call timeout. |
| NFR-3 | All embedding logic is isolated in `src/embeddings.py` — no OpenAI calls in scripts or other modules. |
| NFR-4 | Unit tests cover text building, price tier logic, PG formatting, and error handling without live API calls. |
| NFR-5 | The backfill script logs `[OK]` / `[SKIP]` per product and prints a summary (total / processed / skipped) on completion. |
| NFR-6 | `OPENAI_API_KEY` must be present at runtime; the module should raise a clear error on import if the key is missing and the caller tries to generate an embedding. |

---

## 4. Technical Constraints

- **DB library:** `psycopg2` (synchronous) — consistent with the rest of `src/db.py`. No new DB library.
- **Embedding storage format:** the `[n1,n2,…]` string literal accepted by psycopg2 when writing to a `vector(1536)` column. No custom psycopg2 type adapter needed.
- **pgvector extension:** must be enabled on both local Postgres and Railway before the migration can run. Verify with `SELECT * FROM pg_available_extensions WHERE name = 'vector';` in both environments before T_E1.
- **OpenAI SDK:** `openai>=1.0.0` (the v1 client API). The same `OPENAI_API_KEY` already used by the Next.js web app.
- **ai_description dependency:** `ai_description` is generated by the planned Anthropic pipeline (spec_ai_descriptions.md, T27+) and does not exist yet. The embedding must include it **when not null** but must work correctly when it is null — both the discovery hook and backfill must handle the null case without error.
- **No new DB write functions in `db.py`:** `store_embedding` lives in `src/embeddings.py` and issues its own `UPDATE` directly via a passed `conn`. This keeps the embedding concern self-contained.
- **Python version:** consistent with the existing project (3.10+).

## 5. Architecture Notes

### Embedding text format

Fields are included in this order; any field that is null, empty string, or missing is omitted:

```
{name}
Merk: {brand}
Categorie: {category}
{ai_description}
Prijssegment: {price_tier_label}
Huidige prijs: €{current_price}
Specs:
{key}: {value}
{key}: {value}
…
```

**Price tier label** — derived from `current_price` and `category`. Thresholds are category-specific because price ranges differ significantly across product types:

| Category | Budget | Middensegment | Premium |
|---|---|---|---|
| headphones | < €100 | €100–€300 | > €300 |
| earbuds | < €50 | €50–€150 | > €150 |
| speakers | < €75 | €75–€250 | > €250 |
| soundbars | < €150 | €150–€500 | > €500 |
| *(unknown / null)* | < €100 | €100–€300 | > €300 |

Returns `"onbekend"` if price is None.

**Specs serialisation:** iterate `specs` JSONB as key/value pairs; skip entries where value is `None`, `""`, or the literal string `"null"`. One `key: value` line per entry.

### Module: `src/embeddings.py`

Five functions, no side effects at import time:

| Function | Signature | Purpose |
|---|---|---|
| `build_embedding_text` | `(product: dict) -> str` | Assembles plain-text input string. Never raises. |
| `get_price_tier` | `(price: float \| None, category: str \| None) -> str` | Returns `"budget"`, `"middensegment"`, `"premium"`, or `"onbekend"`. |
| `generate_embedding` | `(text: str) -> list[float] \| None` | Calls OpenAI API; returns None and logs WARNING on any failure. |
| `format_embedding_for_pg` | `(embedding: list[float]) -> str` | Formats as `[n1,n2,…]` for psycopg2. |
| `store_embedding` | `(conn, product_id: int, embedding: list[float]) -> None` | Issues `UPDATE products SET embedding = %s WHERE id = %s` and commits. |

### Discovery hook placement

```
upsert_product()
  └─ [if T27+ done] write ai_description
  └─ [T_E5] if embedding IS NULL:
       fetch row → build text → generate → store
       on failure: log WARNING, continue
```

The hook queries `embedding IS NULL` after upsert so it is idempotent — re-running discovery never overwrites an existing embedding.

### Backfill query

```sql
SELECT id, name, brand, category, specs, ai_description, current_price
FROM products
WHERE embedding IS NULL AND active = true
ORDER BY id;
```

`current_price` is sourced from `price_history` via a subquery or the latest row — confirm the exact column/join during T_E4 (see Risks §7).

### ivfflat index

`lists = 100` is appropriate for a few hundred to low thousands of products and supports fast cosine similarity search. Can be re-created with a higher `lists` value if the product catalogue grows significantly (no data loss, just an index rebuild).

## 7. Risks / Ambiguities

| # | Risk / Ambiguity | Mitigation |
|---|---|---|
| R-1 | **pgvector not available on Railway.** Railway's managed Postgres may not have the extension pre-installed. | Run `SELECT * FROM pg_available_extensions WHERE name = 'vector';` in the Railway DB console before writing any migration code. Block T_E1 until confirmed. |
| R-2 | **`current_price` not on the products table.** The schema has no `current_price` column; price lives in `price_history`. The backfill query and discovery hook need to source the latest price. | During T_E4, confirm whether to JOIN `price_history` for latest price or whether a `current_price` column will be added as part of another task. The embedding text gracefully omits price if null. |
| R-3 | **`ai_description` not yet implemented (T27+).** Embeddings generated before T27+ will be missing the description field. | Acceptable — FR-5 says embeddings are never regenerated unless null. Once T27+ lands and descriptions are backfilled, a second embedding backfill pass can be run if richer embeddings are desired. Flag this as a conscious trade-off. |
| R-4 | **ivfflat index requires rows to exist before it is useful.** An index built on an empty (or near-empty) table has poor query performance until the catalogue is populated. | Apply the index in the migration regardless; it will become effective after the backfill run. No action needed beyond awareness. |
| R-5 | **Rate limit from OpenAI.** `text-embedding-3-small` has generous rate limits, but a large backfill (800+ products) could hit RPM limits. | 100ms sleep gives ~10 req/s, well within free-tier limits. If throttled, increase sleep to 500ms in `--limit` test runs before running full backfill. |
| R-6 | **Specs JSONB structure varies by category.** Key names differ across headphones, earbuds, speakers, soundbars. | `build_embedding_text` iterates whatever keys are present — no hardcoding. No special handling needed. |

### T_E1 — Verify pgvector and apply schema migration

**Phase:** 1  
**Files:** `sql/migrations/005_add_embedding_column.sql`, `sql/migrations/rollback_005_add_embedding_column.sql`, `sql/schema.sql`

Steps:
1. Run `SELECT * FROM pg_available_extensions WHERE name = 'vector';` on local Postgres and Railway DB console. **Stop here if not available on Railway.**
2. Create `sql/migrations/005_add_embedding_column.sql`:
   ```sql
   CREATE EXTENSION IF NOT EXISTS vector;
   ALTER TABLE products ADD COLUMN IF NOT EXISTS embedding vector(1536);
   CREATE INDEX IF NOT EXISTS idx_products_embedding
     ON products USING ivfflat (embedding vector_cosine_ops) WITH (lists = 100);
   ```
3. Create `sql/migrations/rollback_005_add_embedding_column.sql`:
   ```sql
   ALTER TABLE products DROP COLUMN IF EXISTS embedding;
   ```
4. Apply locally via pgAdmin. Verify with `\d products`.
5. Apply on Railway.
6. Update `sql/schema.sql` to include the column and index.
