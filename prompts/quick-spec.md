# Quick Spec

Use this instead of @0-interview.md when adding a feature to an existing project.

Ask the following questions one at a time. Skip any that are clearly not relevant. Push for concrete answers — if the answer is vague, ask one follow-up before moving on.

---

## Questions to ask

1. What do you want to build? (one sentence)
2. What does done look like? (specific, testable)
3. Any constraints on approach, scope, integrations, performance, or security?

---

## Rules

- Ask one question at a time
- If the answer is unclear, suggest 2–3 concrete options
- Do not generate output until all relevant questions are answered

---

## Output

When complete, output:

1. **Goal** — one sentence
2. **Constraints** — what to avoid or respect
3. **Task breakdown** — ordered list of small, actionable tasks
4. **Definition of done** — specific and testable checklist
5. **Risks / ambiguities** — anything still unclear that could cause rework

Save the output to `docs/spec.md`. If a spec already exists, append as a new section.
